# Хранение и загрузка сохранений

Сохранения относятся к нативной части приложения. Эмулятор участвует только через слой `native::save`: он даёт снимок блока commander и принимает загруженный блок, а также ставит одноразовые хуки перехода на станцию. Нативный код не хранит игровые данные в своих структурах.

## Каталог

Все сохранения лежат в одном бинарном файле `saves.bin` в стандартном пользовательском каталоге данных:

- Linux — `$XDG_DATA_HOME/FSA/Elite/saves.bin`, при отсутствии `XDG_DATA_HOME` — `~/.local/share/FSA/Elite/saves.bin`;
- macOS — `~/Library/Application Support/FSA/Elite/saves.bin`;
- Windows — `%APPDATA%\FSA\Elite\saves.bin`.

Путь строится из `dirs::data_dir()` с явными компонентами `FSA/Elite`. `ProjectDirs` не сохраняет вендор на Linux, поэтому путь собирается вручную.

Файл состоит из заголовка `FSAELITE` (8 байт), версии `u32`, числа записей `u32` и записей фиксированной длины. Одна запись — 130 байт:

| Поле | Длина | Содержимое |
| --- | --- | --- |
| `NAME` | 10 | имя командира, только `A-Z` и пробел |
| `COMMENT` | 10 | печатные символы `0x20..=0x7E` |
| `saved_at` | 8 | штамп времени UTC, `i64` в little-endian |
| `data` | 102 | неизменный блок commander оригинальной игры |

Метаданные не смешиваются с блоком игры: 102 байта внутри записи — те же байты, что раньше писались в отдельный файл. Это сохраняет оригинальный формат и позволяет экспортировать/импортировать отдельные сохранения без конверсии.

Перезапись каталога идёт через временный файл с последующей заменой; прежний файл на время замены хранится в `saves.bak`. Повреждённый catalog не переписывается молча: при чтении проверяются magic, версия и точная длина.

Имя ограничено десятью символами, потому что в блоке `#00..#0A` отведено 11 байт: 10 символов и завершающий `0x00`. При сохранении имя вписывается и в 102-байтовый блок, байт `#0A` остаётся нулевым. Комментарий умышленно сокращён до 10 символов: на экране ZX 32x24 вместе с `NAME` (10) и `DATE` (11) в одной строке больше не помещается.

## Экран сохранения

Родная клавиша сохранения (Right Shift), пункт `SAVE` меню `Esc` и запрос `MenuSaveLoad` открывают одно полноэкранное приглашение. Оно рисуется в HD-слое теми же цветами и двухцветным заголовком, что и меню паузы.

- `NAME` заполняется из текущего блока commander: игрок может подтвердить его или дописать;
- `COMMENT` начинается пустым;
- `Tab`, `ArrowUp`, `ArrowDown` переключают поле, `Enter` на `NAME` переводит в комментарий;
- `Backspace` стирает символ, `Esc` отменяет сохранение;
- второй `Enter` записывает запись в каталог.

Ввод имени допускает только латинские буквы (регистр не важен) и пробел; комментарий — ASCII `0x20..=0x7E`. Ограничение длины проверяется при вводе и повторно при записи. Z80 на время экрана заморожен.

## Экран загрузки

Пункт `LOAD` меню `Esc` открывает таблицу всех записей каталога, отсортированных по убыванию штампа времени. Колонки `NAME`, `COMMENT`, `DATE` помещаются в 32 знакоместа: имя — 10, комментарий — 10, дата — `YY-MM-DD` (8). Строки рисуются с шагом в одну строку текста, чтобы в кадре 256x192 помещалось как можно больше записей.

Клавиши в таблице:

| Клавиша | Действие |
| --- | --- |
| `Up`/`Down` | выбор записи |
| `Enter` | загрузить выбранную запись и уйти на станцию без заставки |
| `E` | экспорт выбранной записи в отдельный файл |
| `I` | импорт файла в каталог |
| `Delete`/`Backspace` | удалить запись из каталога |
| `Esc` | закрыть таблицу |

Экспорт пишет ровно 102 байта в файл `elite-ГГГГ-ММ-ДД_ЧЧ-ММ-СС.zxelite`, где дата берётся из штампа записи. Импорт принимает только файл ровно на 102 байта. В таблице дата импортированной записи — `mtime` исходного файла, а в комментарий пишется время импорта в виде `IMP ЧЧ:ММ`: 10 символов комментария не позволяют сохранить полную дату.

Загрузка через `native::request_load` копирует блок в живой и теневой буфер commander и ставит одноразовые хуки на `GameMain` и точки цикла заставки. Хук уводит игру прямо на станцию: родная загрузка возвращалась бы на заставку и ждала `Space`, а для загруженных данных это лишний шаг. Теневой буфер обязателен: `InitGame` восстанавливает пилота именно из него.

## Стартовая загрузка

`--save FILE` — только стартовая загрузка внешнего 102-байтового файла. Файл импортируется в каталог, блок ложится в память, и `request_load` уводит игру на станцию, минуя заставку. Обычные SAVE/LOAD в игре работают только с каталогом. В headless-режиме `--save` не задаёт путь записи: при запросе сохранения headless пишет отдельный файл с именем по умолчанию.
