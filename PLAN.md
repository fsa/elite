## События отображения текста

### Задача

Перехватывать готовый текст, который игра печатает в нижней строке экрана
(`row == 0x0D`), и показывать его нативным видом полёта по центру. Перехват
работает только в режимах View: на заставке, карте, станции и в меню он
выключен.

Строка может приходить несколькими кусками (в том числе в разных кадрах) и
с пропущенными колонками. Поэтому текст хранится не в растущей строке, а в
буфере на 32 колонки: символ из колонки `col` ложится в ячейку `col`. Буфер
живёт всё время показа надписи, а событие всегда содержит всю строку с
обрезанными пустыми началом и концом.

Остальные надписи (подписи вида, отсчёт прыжка, индикаторы) нативный рендер
рисует сам, поэтому их перехватывать не нужно.

### Модель кодировки

Считать, что игра использует обычную печатную кодировку:

- `0x20..0x7E` — печатные символы (латиница, цифры, пунктуация);
- `< 0x20` — управляющие коды, на экран не печатаются;
- `>= 0x7F` — не печатается: `0x7F` не используется, а внутренние коды таблиц
  (`>= 0x80`) раскрываются раньше печати.

Перехват делается **после** раскрытия токенов и преобразования регистра,
поэтому никакой разбор таблиц не нужен.

Исключения, которые надо учесть при формировании текста:

| Код | На экране | В событие |
|---|---|---|
| `0x2A` | `!` | `!` |
| `0x40` | `_` | `_` |
| `0x21..0x26` | служебные значки | пропустить, это не текст |
| остальные `0x20..0x7E` | ASCII | как есть |

`0x28`/`0x29` и `0x3F` — обычные `(`, `)`, `?`; рендер всё равно рисует своим
шрифтом, поэтому сдвиги и толщина оригинала не важны.

### Точка перехвата

`sub_5DFB` (`0x5DFB`), где уже стоит нативный хук `font_base_hook`:

- `A` — окончательный код символа (после регистра и раскрытия токенов);
- `CrdXPrnSymbol` (`0xD045`) — точная текстовая ячейка глифа: младший байт —
  колонка `0..31`, старший — строка `0..23`.

Проверенные факты, на которых это держится:

- `sub_D499` — единственная рутина, которая рисует готовый глиф;
- `sub_5DFB` вызывается только из неё, уже после сдвига курсора, поэтому
  позиция в `CrdXPrnSymbol` — это именно та ячейка, куда ляжет символ;
- коды `< 0x20` и `>= 0x80` до `sub_5DFB` не доходят, поэтому `A` всегда
  в диапазоне печатных символов.

Отдельный хук на `sub_D499` не нужен. Эмуляцию `font_base_hook` не менять: он
остаётся эквивалентным Z80 по регистрам, памяти, `R` и тактам.

### Событие

```rust
/// Готовая строка, которую игра вывела на экран.
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct TextEvent {
    /// Текст в обычной печатной кодировке.
    pub text: String,
    /// Текстовая строка ZX (0..=23).
    pub row: u8,
    /// Колонка первого символа (0..=31).
    pub col: u8,
}
```

`row`/`col` остаются в событии для отладки; `col` — первая непустая
колонка собранной строки. Сейчас перехватывается только нижнее
сообщение — `row == BOTTOM_MESSAGE_ROW` (`0x0D`); события других строк
отбрасываются.

Кроме текста, перехват читает состояние сообщения из памяти игры:

- `msgNumber` (`0xDA76`) — номер/токен сообщения;
- `msgTimeLife` (`0xDA73`) — остаток тактов показа.

Игра перепечатывает надпись каждые несколько кадров, уменьшая `msgTimeLife`.
Когда приходит новое сообщение, счётчик снова взводится вверх. По смене
`msgNumber` или по росту `msgTimeLife` перехват понимает, что началась новая
надпись, и очищает буфер.

### Сборка строк

В `GameMsgTap` — отдельный перехватчик `TextCapture`:

- `render_events: Vec<TextEvent>` — готовые строки для нативного вида
  (ограниченная очередь; рендер забирает её раз в кадр);
- `buffer: [u8; 32]` — колонки нижней строки; пробел — пустая ячейка;
- `message: Option<MessageTag>` — сообщение, которому принадлежит буфер;
- `touched` — печаталось ли что-то в нижнюю строку в текущем кадре.

На каждый символ из `font_base_hook`:

1. Если перехват выключен или `row != 0x0D` — ничего не делать.
2. Коды вне `0x20..0x7E` игнорировать.
3. Если `msgNumber` сменился или `msgTimeLife` вырос — очистить буфер:
   началась новая надпись.
4. Заменить `0x2A` на `!`, `0x40` на `_`; для `0x21..0x26` (служебные значки)
   положить пробел — они занимают колонку, но не являются текстом.
5. Записать символ в `buffer[col]` и взвести `touched`.

В конце каждого кадра вызвать `end_text_frame()`: если в кадре что-то
печаталось, собрать всю строку из буфера, обрезать пробелы по краям и
положить её в очередь рендера. Буфер при этом не очищается — он живёт до
конца надписи. Одинаковые события не схлопывать: игра перепечатывает
сообщение, и каждый повтор — сигнал «надпись ещё на экране». Если куски
строки пришли в разных кадрах, второе событие уже содержит всю строку
целиком.

### Встраивание

1. `src/machine/game_msg.rs` — `TextEvent`, `MessageTag`,
   `BOTTOM_MESSAGE_ROW`, `BOTTOM_MESSAGE_LEN`, `TextCapture`,
   `capture_text_char_tagged(c, row, col, tag)`, `end_text_frame()`.
2. `src/native/text.rs` — в `font_base_hook` читать `row`/`col` из
   `CrdXPrnSymbol`, `msgNumber`/`msgTimeLife` из памяти игры и вызывать
   `capture_text_char_tagged`.
3. `src/machine/mod.rs` — в `run_frame_once` после цикла эмуляции вызывать
   `game_msg.end_text_frame()`.
4. `src/native/mod.rs` — `install_text_capture`: при необходимости ставить
   только хук `0x5DFB`; работает и без `--native`.
5. `src/boot.rs` — включать перехват при старте приложения.

### Вывод в рендере

1. `src/app/frame.rs` — включать перехват только на нативном виде полёта
   (`flight.active && !hdmap.active && !shop.active && !intro_seen && !menu`);
   при смене состояния `GameMsgTap::set_capture` очищает буфер и очереди.
   Раз в кадр старить сообщение и забирать готовые `TextEvent`.
2. `src/flight/messages.rs` — хранить только нижнее сообщение `row == 0x0D`;
   подписи вида и отсчёт рендер рисует сам, без перехвата.
3. Время показа ведёт рендер, а не игра:
   - пришло событие — показать текст и сбросить возраст;
   - пришёл повтор того же текста — снова сбросить возраст;
   - прошло `BOTTOM_MSG_TTL` (16 кадров) без событий — убрать сообщение;
   - при выходе из полёта очищать сообщение сразу.
4. `src/flight/render/mod.rs` — рисовать нижнее сообщение по центру вида
   своим шрифтом; `row`/`col` из ZX-строки не используются.

### Тесты

- `0x2A` → `!`, `0x40` → `_`.
- `0x21..0x26` не попадают в текст; занятая ими колонка остаётся пробелом.
- Соседние символы одной строки дают одно событие с правильными `row`/`col`.
- Разрыв позиции и куски из разных кадров дают в итоге одну строку с
  сохранёнными внутренними пробелами.
- Новая надпись (`msgNumber` сменился или `msgTimeLife` вырос) очищает буфер:
  хвост старой строки не остаётся.
- Пустые начало и конец строки обрезаются.
- Символы всех строк, кроме `0x0D`, игнорируются.
- `end_text_frame()` отправляет напечатанную за кадр строку.
- При выключенном перехвате событий нет; выход из вида очищает очередь.
- Прогон реальной игры: сообщение о гиперпрыжке приходит одним событием в
  `row == 0x0D` и содержит ровно тот текст, который рисует игра.
- `font_base_hook` остаётся эквивалентным Z80.

### Границы

- Исходники игры (`zx_src`, `zx_bin`, `kladov`) не менять.
- Вся логика «что игра напечатала» — в перехвате; вся логика «как это
  показать» — в рендере.
- Перехватчик отдаёт рендеру только нижнюю строку (`0x0D`).
- Перехват включается только на нативном виде полёта; на заставке, карте,
  станции и в меню он выключен.
