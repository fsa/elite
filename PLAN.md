## События отображения текста

### Задача

Перехватывать готовый текст, который игра печатает в нижней строке экрана
(`row == 0x0D`), сохранять его в `debug.log` рядом с исполняемым файлом и
показывать нативным видом полёта по центру.

Остальные надписи (подписи вида, отсчёт прыжка, индикаторы) нативный рендер
рисует сам, поэтому их перехватывать не нужно.

### Модель кодировки

Считать, что игра использует обычную печатную кодировку:

- `0x20..0x7E` — печатные символы (латиница, цифры, пунктуация);
- `< 0x20` — управляющие коды, на экран не печатаются;
- `>= 0x7F` — не печатается: `0x7F` не используется, а внутренние коды таблиц
  (`>= 0x80`) раскрываются раньше печати.

Перехват делается **после** раскрытия токенов и преобразования регистра,
поэтому никакой разбор таблиц не нужен.

Исключения, которые надо учесть при формировании текста:

| Код | На экране | В событие |
|---|---|---|
| `0x2A` | `!` | `!` |
| `0x40` | `_` | `_` |
| `0x21..0x26` | служебные значки | пропустить, это не текст |
| остальные `0x20..0x7E` | ASCII | как есть |

`0x28`/`0x29` и `0x3F` — обычные `(`, `)`, `?`; рендер всё равно рисует своим
шрифтом, поэтому сдвиги и толщина оригинала не важны.

### Точка перехвата

`sub_5DFB` (`0x5DFB`), где уже стоит нативный хук `font_base_hook`:

- `A` — окончательный код символа (после регистра и раскрытия токенов);
- `CrdXPrnSymbol` (`0xD045`) — точная текстовая ячейка глифа: младший байт —
  колонка `0..31`, старший — строка `0..23`.

Проверенные факты, на которых это держится:

- `sub_D499` — единственная рутина, которая рисует готовый глиф;
- `sub_5DFB` вызывается только из неё, уже после сдвига курсора, поэтому
  позиция в `CrdXPrnSymbol` — это именно та ячейка, куда ляжет символ;
- коды `< 0x20` и `>= 0x80` до `sub_5DFB` не доходят, поэтому `A` всегда
  в диапазоне печатных символов.

Отдельный хук на `sub_D499` не нужен. Эмуляцию `font_base_hook` не менять: он
остаётся эквивалентным Z80 по регистрам, памяти, `R` и тактам.

### Событие

```rust
/// Готовая строка, которую игра вывела на экран.
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct TextEvent {
    /// Текст в обычной печатной кодировке.
    pub text: String,
    /// Текстовая строка ZX (0..=23).
    pub row: u8,
    /// Колонка первого символа (0..=31).
    pub col: u8,
}
```

Никаких номеров сообщений и `msgTimeLife`: для показа достаточно текста;
`row`/`col` остаются в событии для журнала и отладки. Сейчас перехватывается
только нижнее сообщение — `row == BOTTOM_MESSAGE_ROW` (`0x0D`); события других
строк отбрасываются.

### Сборка строк

В `GameMsgTap` — отдельный перехватчик `TextCapture`:

- `log_events: Vec<TextEvent>` — готовые строки, ещё не записанные в файл;
- `render_events: Vec<TextEvent>` — готовые строки для нативного вида
  (ограниченная очередь; рендер забирает её раз в кадр);
- текущую строку: `row`, `col`, `text` и `last_col` — ячейку последнего
  напечатанного символа (включая пропущенные значки).

На каждый символ из `font_base_hook`:

1. Если перехват выключен — ничего не делать.
2. Если `row != 0x0D` — игнорировать.
3. Коды вне `0x20..0x7E` игнорировать. Для `0x21..0x26` (служебные значки)
   только обновить `last_col`: они занимают ячейку, но не являются текстом.
4. Заменить `0x2A` на `!`, `0x40` на `_`.
5. Если строка та же и `col == last_col + 1` — дописать символ.
6. Иначе завершить текущую строку (если не пуста), положить в `events` и
   начать новую.

`last_col` нужен вместо `text.len()`, иначе значок в середине строки разорвал
бы её на два события.

В конце каждого кадра вызвать `end_text_frame()`: завершить накопленную строку,
дописать её в `debug.log` и положить в очередь рендера. Одинаковые события не
схлопывать: игра перепечатывает сообщение, и каждый повтор — сигнал «надпись
ещё на экране».

### Журнал

- Файл: `debug.log` рядом с исполняемым файлом (`current_exe()`), иначе — в
  текущем каталоге.
- При старте файл прошлого запуска перезаписывается, дальше строки
  дописываются по мере появления.
- Формат: `[RR:CC] текст`, например `[13:06] Hyperspace -- Lave`.

### Встраивание

1. `src/machine/game_msg.rs` — `TextEvent`, `BOTTOM_MESSAGE_ROW`, `TextCapture`,
   `capture_text_char(c, row, col)`, `end_text_frame()`.
2. `src/native/text.rs` — в `font_base_hook` читать `row`/`col` из
   `CrdXPrnSymbol` и вызывать `m.game_msg.capture_text_char(cpu.a, row, col)`.
3. `src/machine/mod.rs` — в `run_frame_once` после цикла эмуляции вызывать
   `game_msg.end_text_frame()`.
4. `src/native/mod.rs` — `install_text_capture`: при необходимости ставить
   только хук `0x5DFB` и начинать журнал; работает и без `--native`.
5. `src/boot.rs` — включать перехват при старте приложения.

### Вывод в рендере

1. `src/app/frame.rs` — раз в кадр старить сообщение и забирать готовые
   `TextEvent` из перехватчика.
2. `src/flight/messages.rs` — хранить только нижнее сообщение `row == 0x0D`;
   подписи вида и отсчёт рендер рисует сам, без перехвата.
3. Время показа ведёт рендер, а не игра:
   - пришло событие — показать текст и сбросить возраст;
   - пришёл повтор того же текста — снова сбросить возраст;
   - прошло `BOTTOM_MSG_TTL` (16 кадров) без событий — убрать сообщение;
   - при выходе из полёта очищать сообщение сразу.
4. `src/flight/render/mod.rs` — рисовать нижнее сообщение по центру вида
   своим шрифтом; `row`/`col` из ZX-строки не используются.

### Тесты

- `0x2A` → `!`, `0x40` → `_`.
- `0x21..0x26` не попадают в текст и не разрывают строку на два события.
- Соседние символы одной строки дают одно событие с правильными `row`/`col`.
- Разрыв позиции даёт два события.
- Символы всех строк, кроме `0x0D`, игнорируются.
- `end_text_frame()` отправляет недописанную строку.
- При выключенном перехвате событий нет.
- Прогон реальной игры: сообщение о гиперпрыжке приходит одним событием в
  `row == 0x0D` и содержит ровно тот текст, который рисует игра.
- `font_base_hook` остаётся эквивалентным Z80.

### Границы

- Исходники игры (`zx_src`, `zx_bin`, `kladov`) не менять.
- Вся логика «что игра напечатала» — в перехвате; вся логика «как это
  показать» — в рендере.
- Перехватчик отдаёт рендеру только нижнюю строку (`0x0D`) и параллельно
  пишет её в `debug.log`.
